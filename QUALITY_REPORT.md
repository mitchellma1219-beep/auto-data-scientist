## Adversarial findings

All of the following are refused or flagged (tests in `tests/adversarial`, `tests/unit/test_sql.py`,
`tests/unit/test_ingest.py`):

- 63 unsafe SQL statements (writes, DDL, multi-statement, file and network readers,
  `ATTACH`, `COPY`, `PRAGMA`, `SET`, catalog tables, dynamic SQL, recursive CTEs, cartesian
  joins). The same file and configuration attacks also fail when sent straight to the
  database connection, bypassing the guard.
- A 400M x 400M join is interrupted at the time limit and the connection stays usable.
- CSV with 60 ragged rows: loaded, 60 rejections reported in the profile and the report.
- Header-only, blank-line and zero-byte files; random bytes under every supported suffix.
- Mixed types and impossible dates in columns; 20 extreme revenue values.
- Leakage: columns recorded with or after the outcome, including ones that are only filled
  in when the outcome happened.
- Contradictory filters, "highest and lowest" in one question, ambiguous date column,
  unknown columns, questions with no aggregation: refused with the reason.
- `DROP TABLE` payloads in questions, cell values, column names, table names and file paths.
- Upload names with `../`, absolute paths, backslashes, `~`, NUL bytes and double suffixes.
- A 301-column table with 20 kB text cells.

### Defects found by testing and fixed

1. A corrupt `.xlsx` raised an uncaught `zipfile.BadZipFile`; it is now a `DataError`.
2. Columns filled in only for one outcome (for example a cancellation date) were not
   flagged as leakage; a missing-value-pattern screen was added and now covers date and
   text columns too.
3. Exact-duplicate removal distorted class rates in low-cardinality data and misfired on a
   two-row table; duplicates are now removed only when a near-unique column shows they are
   repeated records, otherwise they are kept with a warning.
4. A file of blank lines produced a report about an empty column; it is now refused.
5. Filter values ending in punctuation were not recognised in questions.
6. Correlations over a 301-column table took 74.5 s (one scipy call per pair); the
   vectorised version takes 0.8 s and matches scipy.
7. Foreign keys such as `customer_id` were treated as metrics.
8. "top N regions by total revenue" was rejected by the translator.
9. Pillow 12.3.0 (pulled in by the optional UI extra) had known CVEs; the extra now requires
   13.0.0 or later.
